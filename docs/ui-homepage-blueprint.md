# UI Homepage Blueprint — Mahoon Art Magazine

این سند قرارداد طراحی صفحه اصلی «مجله هنری ماهون» است. تا زمانی که این Blueprint مبنای اجرا قرار نگرفته، نباید فایل‌های کد صفحه اصلی یا استایل عمومی تغییر کنند.

هدف صفحه اصلی، نمایش یک مجله هنری خلوت، فارسی، گرم، لوکس و سریع است؛ نه یک سایت خبری، نه CMS خام، و نه بازنشر یا ویترین زیرساخت فنی.

## 1. اصل طراحی

- ماهون باید در نگاه اول مثل یک مجله هنری مستقل دیده شود: آرام، دقیق، فرهنگی و قابل اعتماد.
- حس بصری باید گرم، هنری، خلوت و لوکس باشد؛ نه شلوغ، تبلیغاتی، تکنیکال یا داشبوردی.
- UI عمومی نباید هیچ اشاره‌ای به تلگرام، Cloudflare، Astro، CMS، ربات، دیتابیس یا زیرساخت فنی داشته باشد.
- Hero جای معرفی برند و حال‌وهوای مجله است؛ جای آمار، شمارنده، کد مطلب، تعداد مطالب یا آخرین شناسه نیست.
- صفحه باید برای خواندن سریع و مرور آرام ساخته شود: عنوان‌ها واضح، فاصله‌ها کنترل‌شده، کارت‌ها جمع‌وجور و بدون فضای خالی بی‌دلیل.
- شعار رسمی ماهون در Hero و Footer قابل استفاده است:

  «درخت هنر، زمانی میوه خواهد داد که ریشه آن خشکیده نشده باشد!»

## 2. قوانین ممنوع

موارد زیر در طراحی و پیاده‌سازی صفحه اصلی ممنوع هستند:

- horizontal page overflow
- scrollbar افقی خام
- carousel در فاز اول
- کارت‌های بسیار بلند، کش‌آمده یا خالی
- فضای سفید بزرگ و بی‌دلیل بین بخش‌ها
- کارت بزرگ و بی‌تعادل برای آخرین مطلب
- باکس آماری، شمارنده، کد مطلب یا وضعیت رسانه در Hero
- دکمه، متن، لینک یا اشاره مستقیم به تلگرام
- متن‌هایی مثل Powered by Cloudflare یا Powered by Astro
- نمایش `view_count`
- استفاده از `min-width` خطرناک که باعث overflow شود
- sectionهای full-width بدون `max-width` کنترل‌شده
- تصویرهای crop شده، بدقواره یا بیرون‌زده از قاب
- متن‌های مکانیکی درباره منطق شماره‌گذاری، شناسه پست یا معماری سیستم
- کارت‌های تو در تو، تزئینات شلوغ، گرادیان‌های غالب و پس‌زمینه‌های تزئینی بی‌ربط

## 3. ساختار نهایی صفحه اصلی

ترتیب بخش‌ها باید دقیقاً این باشد:

1. Header
2. Hero
3. Latest Post
4. Search
5. Posts Grid
6. Footer
7. Scroll to Top

### Header

- ارتفاع هدف: 64 تا 72 پیکسل.
- محتوا داخل container کنترل‌شده با `max-width` صفحه قرار بگیرد.
- لوگو در سمت راست قرار بگیرد.
- نام مجله کنار لوگو باشد: «مجله هنری ماهون».
- nav ساده و کوتاه باشد:
  - خانه
  - درباره ماهون
  - تماس
- Header نباید CTA تبلیغاتی، دکمه تلگرام، badge تکنیکال یا متن اضافه داشته باشد.
- در موبایل، Header باید فشرده و خوانا بماند؛ اگر فضا کم شد nav می‌تواند کوتاه‌تر یا خطی‌تر شود، اما نباید overflow بسازد.

### Hero

- Hero داخل container با `max-width` حدود 1120px قرار بگیرد.
- فاصله از Header حدود 32px باشد.
- ارتفاع desktop حدود 300 تا 360px باشد.
- ارتفاع موبایل حدود 240 تا 300px باشد.
- فرم کلی Hero یک کارت burgundy ساده با گوشه‌های نرم است.
- گوشه‌ها نرم اما کنترل‌شده باشند؛ حدود 18 تا 24px کافی است.
- متن‌ها باید راست‌چین و خوانا باشند.
- محتوای Hero:
  - عنوان کوچک یا برند: «مجله هنری ماهون»
  - headline اصلی: «روایت هنر، تصویر، صدا و نوشتار»
  - شعار: «درخت هنر، زمانی میوه خواهد داد که ریشه آن خشکیده نشده باشد!»
- یک visual ظریف مجاز است؛ مثل لوگو، pattern بسیار کم‌رنگ، یا موتیف ساده برگرفته از هویت ماهون.
- visual نباید خوانایی متن را کم کند و نباید Hero را شلوغ کند.
- Hero نباید هیچ عدد، آمار، کد مطلب، شمارنده، وضعیت رسانه یا متن فنی نمایش دهد.
- در موبایل، متن‌ها باید کوتاه، بدون overlap و بدون نیاز به اسکرول افقی دیده شوند.

### Latest Post

- این بخش بلافاصله بعد از Hero بیاید.
- فاصله عمودی از Hero حدود 40 تا 56px باشد.
- عنوان سکشن: «آخرین مطلب».
- فقط یک کارت برای آخرین مطلب نمایش داده شود.
- کارت باید استاندارد، متعادل و جمع‌وجور باشد؛ نه یک hero دوم.
- چیدمان desktop:
  - grid دو ستونه با نسبت 45/55 یا 40/60
  - ستون رسانه در سمت راست یا چپ بسته به ترکیب نهایی RTL، اما تعادل بصری باید حفظ شود
  - ارتفاع کل کارت حدود 320 تا 380px
- چیدمان موبایل:
  - تک‌ستونه
  - ارتفاع auto
  - بدون فضای خالی بزرگ زیر تصویر یا متن
- اگر پست تصویر دارد:
  - رسانه داخل قاب ثابت قرار بگیرد.
  - نسبت قاب 4/3 یا 16/10 باشد.
  - `object-fit: cover` فقط وقتی مجاز است که crop آزاردهنده ایجاد نکند.
  - اگر تصویر برای crop مناسب نیست، `contain` داخل قاب کنترل‌شده ترجیح دارد.
- اگر پست text-only است:
  - به جای فضای خالی یا placeholder خام، poster متنی اختصاصی نمایش داده شود.
  - poster compact باشد و حس یادداشت هنری بدهد.
  - poster می‌تواند gradient یا texture بسیار ظریف داشته باشد.
- محتوای متنی کارت:
  - title
  - excerpt کوتاه، حداکثر 2 تا 3 خط
  - tagهای محدود، ترجیحاً حداکثر 2 یا 3 عدد
  - CTA با متن «ادامه مطلب»
- در کارت latest نباید `view_count`، کد مطلب، telegram metadata یا متن زیرساختی نمایش داده شود.

### Search

- Search زیر Latest Post قرار بگیرد.
- فاصله از Latest حدود 28 تا 36px باشد.
- input ارتفاع حدود 54px داشته باشد.
- `font-family` باید `inherit` باشد.
- placeholder دقیق:

  «جست‌وجو در مطالب...»

- Search فقط برای جست‌وجوی محتوای مطالب است.
- متن یا placeholder نباید به کد مطلب، شماره ربات یا شناسه دیتابیس اشاره کند.
- در موبایل، input باید عرض 100% و touch-friendly باشد.

### Posts Grid

- عنوان سکشن: «همه مطالب».
- grid داخل همان container اصلی صفحه قرار بگیرد.
- فاصله Search تا عنوان یا grid باید کنترل‌شده و کوتاه باشد؛ حدود 32 تا 40px.
- چیدمان desktop:
  - سه ستون
  - gap حدود 24px
- چیدمان tablet:
  - دو ستون
  - gap حدود 20 تا 24px
- چیدمان mobile:
  - یک ستون
  - کارت‌ها با عرض 100%
- کارت‌ها:
  - min-height کنترل‌شده داشته باشند.
  - از نظر بصری max-height کنترل‌شده داشته باشند.
  - متن اضافه نباید کارت را بیش از حد بلند کند.
  - فضای خالی بزرگ داخل کارت ممنوع است.
- media:
  - نسبت ثابت 4/3 یا 16/10 داشته باشد.
  - تصویر یا poster باید قاب را کامل و تمیز پر کند.
- excerpt:
  - حداکثر 3 خط، با line-clamp یا کنترل معادل.
- tags:
  - حداکثر 2 یا 3 عدد.
- CTA:
  - متن «ادامه مطلب».
- grid نباید در هیچ breakpoint افقی اسکرول ایجاد کند.

### Footer

- Footer ساده، کوتاه و مرتب باشد.
- محتوا داخل container کنترل‌شده قرار بگیرد.
- شامل این موارد باشد:
  - نام مجله
  - شعار ماهون
  - لینک‌های خانه، درباره، تماس، RSS
- Footer نباید به تلگرام، Cloudflare، Astro، CMS، ربات یا زیرساخت فنی اشاره کند.
- ارتفاع Footer باید کنترل‌شده باشد؛ نباید به بخش بزرگ و خالی تبدیل شود.
- در موبایل، لینک‌ها می‌توانند wrap شوند، اما نباید overflow افقی بسازند.

### Scroll to Top

- دکمه کوچک، ثابت یا anchor ساده مجاز است.
- اگر ثابت است، در گوشه پایین قرار بگیرد و مزاحم محتوای موبایل نباشد.
- اگر anchor است، در انتهای محتوا یا Footer قرار بگیرد.
- نمایش آن می‌تواند فقط بعد از اسکرول فعال شود.
- اندازه باید touch-friendly باشد، اما نباید روی کارت‌ها یا CTAها را بپوشاند.

## 5. رفتار موبایل

- در هیچ عرضی overflow افقی نباید ایجاد شود.
- تست ویژه باید زیر 390px انجام شود.
- Header باید خلوت بماند و متن‌ها نباید روی هم بیفتند.
- Hero باید کوتاه‌تر، خواناتر و بدون visual مزاحم باشد.
- Latest باید تک‌ستونه باشد و فاصله‌های داخلی آن کم اما تنفس‌دار بماند.
- Grid باید یک‌ستونه باشد.
- همه کارت‌ها باید عرض 100% container را بگیرند.
- CTAها، لینک‌ها و input باید touch-friendly باشند.
- اندازه فونت‌ها باید خوانا بماند و با viewport scaling خام تغییر نکند.
- Footer باید مرتب wrap شود و ارتفاع بی‌دلیل نگیرد.

## 6. رفتار text-only posts

- پست text-only باید poster اختصاصی داشته باشد.
- poster نباید مثل missing image، placeholder خام یا مستطیل خالی دیده شود.
- poster باید compact باشد و نسبت ثابت media را حفظ کند.
- ظاهر poster می‌تواند شامل این عناصر باشد:
  - رنگ گرم و هماهنگ با هویت ماهون
  - texture یا gradient بسیار ظریف
  - تیتر کوتاه یا موتیف تایپوگرافیک کنترل‌شده
  - نشانه بصری ساده و کم‌رنگ
- poster نباید متن طولانی را داخل خود حبس کند.
- هدف poster این است که پست text-only حس یادداشت هنری و مجله‌ای داشته باشد.

## 7. رفتار image posts

- تصویر هر پست باید داخل قاب ثابت نمایش داده شود.
- نسبت قاب باید برای latest و grid از قبل مشخص باشد.
- crop نباید چهره، اثر هنری، نوشته یا سوژه اصلی را خراب کند.
- `object-fit` باید با aspect-ratio کنترل شود:
  - `cover` برای تصاویر مناسب و قاب‌های قابل crop
  - `contain` برای آثاری که crop شدنشان آسیب‌زننده است
- تصویر نباید ارتفاع کارت را از کنترل خارج کند.
- loading تصویر نباید باعث layout shift بزرگ شود.

## 8. تست‌های قبولی قبل از deploy

قبل از هر deploy، این تست‌ها باید انجام و تأیید شوند:

- no horizontal scrollbar در desktop، tablet و mobile.
- کارت latest فضای خالی بزرگ ندارد.
- grid در سه ستون، دو ستون و یک ستون درست کار می‌کند.
- mobile زیر 390px خراب نمی‌شود.
- Search کار می‌کند و placeholder درست دارد.
- پست‌ها لود می‌شوند.
- SEO head سالم است.
- Article JSON-LD سالم است.
- `view_count` در UI عمومی وجود ندارد.
- Cloudflare، Astro و Telegram در UI عمومی دیده نمی‌شوند.
- Hero هیچ عدد، آمار، کد مطلب یا metadata فنی ندارد.
- پست‌های text-only poster اختصاصی و compact دارند.
- پست‌های image داخل قاب ثابت و بدون crop آزاردهنده دیده می‌شوند.
- `git diff` فقط فایل‌های مجاز همان فاز را نشان می‌دهد.
- قبل از deploy، local preview حتماً تأیید چشمی شود.

## 9. فایل‌های مجاز برای implementation بعدی

در فاز implementation بعدی، فقط این فایل‌ها مجاز هستند:

- `website/dreary-disk/src/pages/index.astro`
- `website/dreary-disk/src/styles/global.css`

فقط اگر واقعاً لازم شد:

- `website/dreary-disk/src/layouts/BaseLayout.astro`

هر تغییر در این فایل‌ها باید کوچک، قابل تست و قابل بازبینی باشد. بعد از تغییر سایت، build باید اجرا شود:

```bash
cd website/dreary-disk
npm run build
```

## 11. قفل اجرایی

- این سند فقط Blueprint است و خودش مجوز تغییر کد نیست.
- implementation بعدی باید از همین ساختار شروع کند.
- اگر در زمان اجرا نیاز به خروج از این Blueprint پیدا شد، ابتدا باید سند به‌روزرسانی و تأیید شود.
- هیچ deploy، commit، push یا اجرای `wrangler` بخشی از این مرحله نیست.
