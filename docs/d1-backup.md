# D1 Backup Guide

این فایل راهنمای بکاپ امن دیتابیس D1 پروژه مجله هنری ماهون است.

## هدف

کدهای سایت و Worker API داخل GitHub ذخیره شده‌اند، اما داده‌های واقعی پست‌ها داخل Cloudflare D1 قرار دارند.

برای جلوگیری از از دست رفتن داده‌ها، باید به‌صورت دوره‌ای از دیتابیس D1 بکاپ گرفته شود.

## وضعیت فعلی

- دیتابیس D1 فعلاً در Cloudflare مدیریت می‌شود.
- Worker API از طریق binding با نام `DB` به D1 وصل است.
- فایل خروجی بکاپ نباید داخل GitHub ذخیره شود.
- هیچ Secret، Token، Database ID یا مقدار واقعی Cloudflare نباید داخل این مستند نوشته شود.
- این سند فقط راهنمای عملیاتی است و هیچ دستور اجرایی را به‌صورت خودکار اجرا نمی‌کند.

## دستور نمونه برای خروجی گرفتن

برای خروجی گرفتن از دیتابیس remote D1، از دستور نمونه زیر استفاده می‌شود:

~~~cmd
npx wrangler d1 export <DATABASE_NAME> --remote --output=<LOCAL_BACKUP_PATH>
~~~

نمونه با placeholder:

~~~cmd
npx wrangler d1 export MAHOON_DB --remote --output=C:\Backups\mahoon\d1-backup-YYYY-MM-DD.sql
~~~

نکته مهم: مسیر خروجی باید بیرون از repository باشد.

## مسیرهای امن نمونه

نمونه مسیرهای امن برای ذخیره موقت بکاپ:

~~~text
C:\Backups\mahoon\
D:\PrivateBackups\mahoon\
~~~

این مسیرها داخل پروژه Git نیستند و احتمال commit شدن تصادفی فایل بکاپ را کم می‌کنند.

## مسیرهای ناامن نمونه

این مسیرها برای ذخیره بکاپ مناسب نیستند، چون داخل repository پروژه قرار می‌گیرند:

~~~text
C:\Users\User\tg-cms\backups\
C:\Users\User\tg-cms\website\
C:\Users\User\tg-cms\workers\
C:\Users\User\tg-cms\docs\
~~~

## قانون امنیتی قبل از commit

قبل از هر commit باید مطمئن شویم فایل‌های بکاپ دیتابیس وارد Git نشده‌اند.

دستورهای بررسی:

~~~cmd
git status
git diff --stat
~~~

اگر فایل‌هایی مثل موارد زیر در `git status` دیده شدند، نباید commit شوند:

~~~text
*.sqlite
*.sqlite3
*.db
*.db3
*.sql
*.dump
*.backup
backups/
~~~

## پیشنهاد برای مرحله بعد

برای جلوگیری از ورود تصادفی فایل‌های دیتابیس به GitHub، بهتر است بعداً موارد زیر به `.gitignore` اضافه شوند:

~~~gitignore
# Database backups
*.sqlite
*.sqlite3
*.db
*.db3
*.sql
*.dump
*.backup
backups/
**/backups/
~~~

این تغییر باید در یک commit جداگانه انجام شود.

## برنامه پیشنهادی بکاپ

پیشنهاد عملیاتی:

- بکاپ دستی هفتگی در شروع کار
- بکاپ قبل از هر تغییر بزرگ در Worker API
- بکاپ قبل از هر تغییر بزرگ در ساختار دیتابیس
- نگهداری حداقل ۳ نسخه آخر بکاپ در مسیر خصوصی خارج از repository
- بررسی فایل خروجی بکاپ بعد از export
- عدم ارسال فایل بکاپ در GitHub، Telegram، ایمیل عمومی یا فضای اشتراکی ناامن

## نام‌گذاری پیشنهادی فایل بکاپ

برای نظم بهتر، نام فایل بکاپ بهتر است شامل تاریخ باشد:

~~~text
d1-backup-YYYY-MM-DD.sql
~~~

نمونه:

~~~text
d1-backup-2026-07-02.sql
~~~

## بازیابی اضطراری

در صورت نیاز به بازیابی، ابتدا باید یک دیتابیس تست ساخته شود و فایل بکاپ روی دیتابیس تست import شود.

بازیابی مستقیم روی دیتابیس اصلی بدون تست اولیه ممنوع است.

دستور import یا هر عملیات بازیابی باید فقط بعد از بررسی کامل و با اجازه مالک پروژه اجرا شود.

## چک‌لیست بکاپ امن

قبل از گرفتن بکاپ:

- مطمئن شو مسیر خروجی بیرون از repository است.
- مطمئن شو نام دیتابیس به‌صورت placeholder در مستندات مانده و مقدار واقعی وارد Git نشده است.
- مطمئن شو فایل خروجی در مسیر خصوصی ذخیره می‌شود.

بعد از گرفتن بکاپ:

- فایل خروجی را بررسی کن.
- فایل بکاپ را داخل GitHub commit نکن.
- قبل از commit بعدی، `git status` را بررسی کن.
- حداقل ۳ نسخه آخر بکاپ را نگه دار.
